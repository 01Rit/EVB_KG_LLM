# V1.3 跨层多跳查询修复 + 向量语义搜索

## 版本信息

- **版本号**: V1.3
- **发布日期**: 2026-05-15
- **标签**: v1.3-cross-layer-query-fix

---

## 概述

本次迭代修复了知识图谱跨层多跳查询的核心问题，并引入了基于 DashScope `text-embedding-v4` 的向量语义搜索能力。修复后，从 L1 Component → L2_Entity → L2_Document/L3_Term 的完整推理链路可以正常工作，自然语言问答能够正确引用 GB/T 国标文档。

---

## 变更详情

### 1. 跨层多跳遍历修复（核心）

**问题**：查询"Audi A3冷却板的国标标准"时，LLM回答"无法确定具体标准"。

**根因**：
1. 第二跳 `L2_Entity → L2_Document` 的关系类型是 `REFERENCED_IN`，但代码限定为 `DEFINITION_OF`，导致文档节点丢失
2. L2_Document 节点使用 `doc_id` 作为主键，没有 `id` 属性，COALESCE 未正确处理
3. LLM 生成时仅取 ranker 排名前10的证据，Documents 排在第12名后被截断

**修复**：

| 文件 | 修改 |
|------|------|
| `src/kg/client.py` | 新增 `get_l2_neighbors()` 替代 `get_l3_by_l2_ids()`，不限关系类型 |
| `src/kg/client.py` | `COALESCE(neighbor.id, neighbor.doc_id, neighbor.term_id)` 统一主键 |
| `src/graphrag/natural_feedback.py` | 第二跳改为无限制关系遍历，按节点标签分类处理 |
| `src/graphrag/natural_feedback.py` | `evidence[:10]` → `evidence[:20]` 增加LLM证据量 |

### 2. 向量语义搜索引入

**问题**：文档检索仅支持关键词匹配（CONTAINS），无法语义理解。

**修复**：
- 使用 DashScope `text-embedding-v4` 模型生成 1536 维嵌入向量
- 创建 Neo4j VECTOR INDEX（`doc_embedding_idx`，COSINE 相似度）
- `search_documents_vector()` 优先于 `search_documents()` 的文本搜索

| 文件 | 修改 |
|------|------|
| `src/kg/client.py` | `compute_embedding()` 改用 DashScope API |
| `src/kg/client.py` | `search_documents_vector()` Neo4j 原生向量检索 |
| `src/kg/client.py` | `build_document_embeddings()` 批量生成 embedding |
| `src/graphrag/retriever.py` | `_retrieve_documents()` 向量搜索优先 |
| `.env` | 新增 `DASHSCOPE_API_KEY` |
| `docker-compose.yml` | 容器传递 `DASHSCOPE_API_KEY` 环境变量 |

### 3. 历史遗留 Bug 修复

本版本一并修复了从 V1.25 继承的三个 GraphRAG 缺陷：

| 文件 | 问题 | 修复 |
|------|------|------|
| `src/kg/client.py` | `get_subgraph()` 中 Neo4j Relationship 对象被误判为 tuple | 改为 `.start_node`/`.end_node`/`.type` 属性访问 |
| `src/kg/client.py` | 节点标签不匹配（查询 `Document`/`Term`，实际为 `L2_Document`/`L3_Term`） | 统一使用 `|` 多标签匹配 |
| `src/kg/client.py` | `get_subgraph()` 起始节点排除 Document/Term | 起始标签扩大覆盖 |

## 架构变更

```
检索前 (V1.25):
  L1 Component → (REFERENCE_OF) → L2_Entity → (DEFINITION_OF → L3_Term)

检索后 (V1.3):
  L1 Component → (REFERENCE_OF) → L2_Entity
                                    ├── (DEFINITION_OF) → L3_Term
                                    ├── (REFERENCED_IN) → L2_Document
                                    └── (任意关系) → 其他关联节点
```
